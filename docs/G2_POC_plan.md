# G2 Scoop & Dump POC：纯 GDK 定点方案

目标：给客户演示 G2 的运动控制。不用相机，不识别桶，不用 ROS；用 AgiBot GDK（Python `agibot_gdk`）按示教好的点位回放 7 步动作。

## 1. 站位：图上的站位区够不着料桶 P1

早期用官方 G2 URDF（crsB + Omnipicker）做的运动学估算。**已确认真机是 crs 手臂**，以第 7 节的 crs 仿真结果为准。本文所有坐标单位为英寸，原点在房间左下角。

- **手能伸多远（夹爪中心到底盘中心，水平距离）：**
  - 在 1.37 m 高度（高出 50 in 料斗沿约 10 cm）：向前约 1.0 m，向侧面约 0.88 m，向后约 0.83 m。
  - 前提：夹爪倾斜不超过 20°，重心偏移不超过 5 cm。
- **图上站位区放得下的范围：** 区域是 (66,42)，36 × 36；G2 底盘 25 × 30 in，所以底盘中心只能在 x 78.6–89.4、y 57–63 之间。
- **从这个范围到两个目标点：**
  - 到 P1（料桶角 ≈ (132,88)）至少约 1.25 m，**够不着**。
  - 到 P2（料斗边 ≈ (62,93)）约 0.87 m，可以够到。

**建议：把站位改到料斗和料桶之间（已用第二套独立 IK 复核）。** 底盘中心放在约 **(93, 88–90)**，**车头朝 +x（朝料桶）**。占地约 x 78–108、y 77–103，离料斗底座 8 in，离料桶 24 in。站着不动、只转腰（idx05，±174.5°）就能两边都够到，**全程不用移动底盘**：
- **取料 P1：** 夹爪竖直向下，TCP 高约 0.80 m（料桶高度待量，0.80–0.95 m 都已验算可达）；用右臂，腰转约 +75°，升降腿把肩部降到约 1.0–1.1 m。
- **倒料 P2：** TCP 高约 1.37–1.42 m，**夹爪朝料斗倾斜约 60°**；腰转约 -50° ~ -66°。
- 从取料到倒料，腰要转约 140–155°，从前方转过去。
- **取料点要靠近料桶左上角（P1 附近 4 in 以内）。** 距离约 1.0 m，已接近夹爪竖直时的极限（1.09–1.17 m），桶里更深的地方够不到。

**图上原站位区的问题：** 站在原站位区，P2 可以够到（要夹爪水平），P1 基本够不着（只能在完全伸直、零余量的姿态下勉强碰到）。

**备选方案：** 中间用 `pnc.relative_move` 移一次底盘，取料站 (110, 76)，倒料站 (88, 96) 或更靠东。(82, 96) 会压到料斗底座 3 in，不能用。这个方案要先在 G02 Pad 上重定位，`relative_move` 只会遇障停车、不会绕行，重复定位精度至少要做到约 2 cm，**POC 不推荐**。

**倒料时的高度窗口（复核时发现的问题）：** 料斗沿 50 in（1.27 m），上方框架顶 63 in（1.60 m，待量）。
- **夹爪竖直向下倒料行不通：** 料斗沿 1.27 m + 0.10 m 余量 + TCP 到手腕 0.233 m = 1.60 m，手腕会顶到框架。
- **改成夹爪倾斜约 60° 倒料：** 手腕约 1.52 m，法兰约 1.47 m，离框架只剩约 8 cm，连杆本身还有约 5 cm 粗。**框架高度必须先实测**，再定倒料姿态。

> 以上是根据 URDF 算的纯运动学结果，没考虑连杆粗细、自身碰撞和环境碰撞，也没考虑真机的力矩和平衡限制。另外 URDF 和 GDK 的关节零位、正负方向可能不一致，上真机前要先确认。示教时一律低速。

## 2. 七个动作和对应的示教点位

每个点都记录 **腰/升降 5 个关节 + 手臂 7 个关节**（不记录腰，回放时手会到错的高度）；头部 3 个关节可以固定。

| 步骤 | 点位 | 动作 |
|---|---|---|
| 0 | `HOME` | 初始姿态 |
| 1 | `ABOVE_BIN` | 移到料桶 P1 上方，**张爪** |
| 2 | `IN_BIN` | **下降**到桶内 |
| 3 | — | **合爪**（假装抓起） |
| 4 | `LIFT` | **抬起**，原路退出桶口 |
| 5 | `TRANSIT` → `PRE_RIM` → `ABOVE_HOPPER` | 抬到约 1.45 m，转腰约 150°，越过桶沿，到料斗 P2 上方，夹爪倾斜约 60°（在框架下面） |
| 6 | — | **张爪**（假装倒料） |
| 7 | `RETREAT` → `HOME` | 退出料斗上方，**回位** |

## 3. GDK 调用（2.6.x / 3.3.x 的 Python 接口）

```python
import agibot_gdk, time
agibot_gdk.gdk_init(); robot = agibot_gdk.Robot(); time.sleep(2.0)   # 等 DDS 连上
robot.set_control_mode(1)                    # 关节位置模式（模式会保留在机器人上，开头先设好）

# 示教：读取当前关节角（用 motor_position，不要用 position）
js = robot.get_joint_states(); q = {s['name']: s['motor_position'] for s in js['states']}

# 回放：阻塞式关节运动，到位后才返回
req = agibot_gdk.JointControlReq()
req.joint_names = names; req.joint_positions = target; req.joint_velocities = [0.2]*len(names)
req.life_time = 10.0; robot.joint_control_request(req)

# 夹爪（Omnipicker）：-0.785 = 张开，0 = 闭合
s = agibot_gdk.JointState(); s.position = -0.785
cmd = agibot_gdk.JointStates(); cmd.group = 'right_tool'; cmd.target_type = 'omnipicker'
cmd.states = [s]; cmd.nums = 1; robot.move_ee_pos(cmd)
# move_ee_pos 总是返回 0，要轮询 get_end_state() 确认夹爪真的动了

agibot_gdk.gdk_release()                     # 退出时经常 SIGABRT，可以忽略
```

**每次运动前的安全检查：**
- `get_whole_body_status()` 里所有 `*_error` 都是 0，两个 `estop` 标志都是 false。
- `get_motion_control_status().error_code` 是 0。

**每次运动后：** 重新读关节角，和目标的误差应在 0.02 rad 以内。

## 4. 示教方法

G2 的 GDK 没有公开的拖动示教接口，用下面的办法：
- 用小步 `joint_control_request` 点动：每步 0.05–0.1 rad，速度 0.1–0.2 rad/s。也可以用 G02 Pad 摆好姿态。
- 摆到位后运行 `record.py <点位名>`，把当前关节角存进 `waypoints.json`。
- 回放脚本 `run_poc.py` 按上面的表依次执行。第一次全程 0.1–0.2 rad/s，确认没问题再提到约 0.3 rad/s。

## 5. 环境

- **开发机：** Ubuntu 22.04 x86_64，网线接 G2 调试口；机器人 10.42.1.101，开发机设 10.42.1.102。
- **安装：** `curl -sSL http://10.42.1.101:8849/install.sh | bash`，每个终端先 `source ~/.cache/agibot/app/env.sh`。
- **Python：** 预编译绑定是 CPython 3.10。也可以直接在机器人本机上跑。
- **防火墙：** 开发机要放行来自 10.42.1.101 的入站连接，否则读数据正常、发指令会卡住。

## 6. 风险和注意事项

1. **GDK 版本差异：** 2.1、2.6、3.3 的接口不完全一样。`set_control_mode` 和 `motion_plan_request` 不在 2.6 的文档里，要在机器人上用 `help()` 确认有没有。你的版本可以在 `http://10.42.1.101:8849` 查到。
2. **没有碰撞检测：** `joint_control_request` 不检查碰撞，所以示教路径本身必须无碰撞。料斗沿和框架附近要多加中间点。
3. **不要用 `end_effector_pose_control`：** 同一个进程里用过它之后，夹爪会不响应。
4. **没有软件急停：** 必须有人手按实体急停。
5. **需要现场测量：** 料桶高度和前开口、料斗上方框架的实际轮廓、门的位置。
6. **一定要用真实料位示教：** 站位改变后，所有点位都要在现场重新示教，不能直接用图上坐标算出来的值。

## 7. MuJoCo 仿真验证结果（2026-11-20 更新）

详见 [sim/README.md](../sim/README.md)。

- **模型来源：** 官方 `AgibotTech/genie_sim_robot_model`（锁定 commit `fb6de33`），crs 手臂 + Omnipicker 夹爪，碰撞外形用官方 `fine` 选项。
- **站位：** 底盘中心 (101.5, 84) in，朝向 +y，全程不动底盘。
- **夹爪：** 倒料时倾斜 75°。“松开”之后先合爪，再退出，否则张开的手指会碰到框架。
- **通过的条件：**
  - crs 手臂；
  - 框架横梁深度不超过 1 in（梁底在 62 in）；
  - 料桶高 30 in。

  在这个条件下，路径检查和物理回放都通过：零碰撞，离工位至少 5.7 cm。
- **不通过的情况：** 框架梁深 3 in，或换成 crsB 手臂，都达不到 5 cm 余量。料桶每高 2 in，余量就降到约 3 cm。
- **手臂型号：** 已确认为 crs（2026-11-20）。
- **上真机前必须做的：**
  - 实测料桶、框架和站位，用实测值重新生成路径；
  - 用 `sim/gdk/run_poc_gdk.py` 分步低速执行。
